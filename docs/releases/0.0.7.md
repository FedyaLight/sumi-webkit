# Sumi 0.0.7

This release fixes first-load extension scripts and permission prompt sequencing, and corrects several everyday browser interactions.

## Highlights

- Extension content scripts now run on the first page loaded in a newly opened tab instead of requiring a reload.
- Dismissing a site permission prompt settles the request and releases the sidebar. Queued prompts advance after the current decision.
- Command-W closes Settings when Settings is focused instead of closing a browser tab behind it.
- The Command Palette no longer repeats the typed search query as a suggestion. Pressing Return searches the entered text unless another result is selected.
- Certificate trust approval stays with the tab for its related page resources, while the URL Hub continues to mark the page as not secure.
- Favicon selection is consistent between the initial load and later page updates. High-quality raster resampling improves diagonal edges, and repeated sidebar reads avoid duplicate repository lookups.

## Download and Updating

- `Sumi-0.0.7-build12-macos-arm64.dmg` is the single immutable artifact for direct installs and Sparkle updates.
- Both Sparkle feeds point eligible Apple-silicon installations to the same signed Arm64 item.
- The appcast hardware requirement is `arm64`. An older Sumi installation on an Apple-silicon Mac can update, including an Intel build running under Rosetta. Native Intel Macs receive no incompatible update.
- Historic Intel and Universal release assets remain available.

## Installation Boundary

The app is development-signed, not Developer ID signed or notarized. If macOS says the app is damaged, move it to `/Applications` and remove the quarantine flag:

```sh
sudo xattr -dr com.apple.quarantine "/Applications/Sumi.app"
open "/Applications/Sumi.app"
```

Run this only for a Sumi bundle intentionally downloaded from the official GitHub Release.
